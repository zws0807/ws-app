# 第一批本机验收记录

日期：2026-11-03。目录：`app/`。本轮仅本机实现；云端资源仍为 TODO。

## 可用范围

React / TypeScript 前端与 Hono Workers API 已整合。D1、私有 R2、Images、DO、原生限流、Queue 后台 Worker 在本机实际运行；Cron 清理入口及测试已实现。业务功能包括注册登录、恢复码与改密、私人图库、自由愿望板、周目标与去重打卡、日期书写和异步 ZIP 导出。

没有创建云账号或资源、推送仓库、部署网站。正式资源、域名和 secrets 见 [RESOURCE_TODO](../../RESOURCE_TODO.md)。年度、十周、会员、音频、AI 和导入恢复按原分期留待后续。

## 复核与修复

独立只读审查反馈集中于草稿与跨服务失败恢复。按实际影响将以下问题作为重要问题处理；每项先复现，再修复，无二次审查循环。

| 问题                                                         | RED → GREEN 证据                                                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 首次读取愿望板失败时，新增内容覆盖既有本机草稿               | 浏览器先找不到旧愿望；修复后旧草稿、新编辑均保留，重试后保存                                     |
| 自定义非周一起止日期的周计划，刷新后无法找回                 | 浏览器找不到计划入口；增加分页的已保存计划选择器后通过                                           |
| 图片 ready 更新已提交但 D1 响应丢失，错误补偿删除原图        | 注入真实 D1 提交后的错误，原图原先变为缺失；修复后 ready 元数据、原图、缩略图一致                |
| ZIP 完成后进程中断，重试或过期只 abort multipart，旧成品遗留 | 真实 R2 完成 multipart 后模拟过期租约；旧对象原先残留，修复后重试和过期均清除                    |
| 日记保存成功但响应丢失，修改后的草稿被相同请求键清空         | 服务端对不同内容返回 409；界面保留输入并换新键，经再次明确保存后两份内容均存在                   |
| ZIP ready 提交响应丢失，补偿误删已完成导出                   | 同类故障注入先复现 ready + 404；核对 D1 状态后，ready 文件仍可下载                               |
| 图库固定 500 条，旧图片不可访问                              | 51 张元数据验证先无分页；修复为每页50张，游标与账号过滤通过                                      |
| 缺少全站注册配额                                             | 将全局 DO 计数预置到1000，原先仍创建账号；修复为24小时1000次预算，创建前429                      |
| 周切换读取失败时，仍可误编辑上一周数据                       | 浏览器先复现旧目标仍可编辑；修复后读取失败显示重试入口，读到所选周后才开放编辑，保存中也禁止切周 |

图片另验证：超过10MB、合法但超过2400万像素的PNG均拒绝，失败不遗留 ready 图片或占用额度。原有鉴权、CAS无副作用、恢复码单次使用、撤销打卡重放、冻结导出快照和 outbox 补发回归均通过。

## 实现取舍与影响

以下列出执行期间全部 Ruling，按发生顺序排列；这是本轮决策记录。

1. 用户已授权按确认架构开发，资源先留 TODO，因此在新 `app/` 本地仓库开发，不再次询问设计、不开额外 worktree、不操作远程。影响：后续集成现有远程仓库需另安排。
2. 本机绑定使用清楚标注的占位标识，发布门禁拒绝 TODO 配置。影响：真实上线必须提供独立生产配置并验收。
3. 公开产物仅为 `dist/client/`，Worker 与开发秘密放在忽略提交的兄弟目录。影响：后续部署不可把整个 `dist/` 当作公开目录。
4. 密码使用 `@noble/hashes` 纯 TypeScript Argon2id，19456KiB / t2 / p1，避免动态 WASM 限制。影响：真实 Workers 的 CPU / 内存仍需 staging 测量；本机通过不代表免费套餐可承受。
5. 本机系统浏览器出现调度停滞，测试改用项目忽略目录中的配套 Chromium；自动流程用真实键盘操作，拖动缩放用真实鼠标。影响：系统浏览器与其他设备仍需上线前兼容验收。
6. Vite 与 Wrangler CLI 明确共用 `app/.wrangler/state`，避免两个数据库目录。影响：移动项目或更换持久目录时需同时核对配置。
7. 注册按来源50次/10分钟；登录、恢复按账号合计10次/10分钟；原生限流1000次/分钟作近似突发防护，DO作严格计数。后续补上全站1000次/24小时注册尝试预算。影响：试用规模变化时需评估配额，不能把来源限制当成身份验证。
8. 在资源留 TODO 的授权范围内保留本地开发分支，不合并、不推送、不发布。影响：当前交付是本机可运行版本。

Deferred minors：本轮已返回的审查意见中没有另外列出的次要问题。未实施的后续业务与远端验证属于原定分期范围。
