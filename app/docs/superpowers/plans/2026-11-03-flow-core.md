# 心流显化核心试用版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可注册、独立保存私人图片与愿望板、完成每周打卡和日期书写的真实核心版本。

**Architecture:** 原型保持只读，正式代码放在独立的 app/。网页与服务端同源运行，由服务端校验身份、读写数据库和私人文件；首先本机验收真实服务，再选择中国大陆可用的上线服务。年度信念、十周关联及会员内容分为后续两个计划，不在本计划中假装完成。

**Tech Stack:** 建议 TypeScript、React/Vite、Node.js 22 LTS、Fastify、SQLite、本地私有文件目录；测试使用 Vitest、服务端请求测试与浏览器端到端测试。均为实施建议；锁定依赖版本、选具体数据库驱动前核实兼容性。上线前根据实际并发、备份和托管能力确认 SQLite 是否继续适用，不直接承诺生产架构不变。

**Spec:** outputs/心流显化-真实试用版设计方案-优化版.md

## Global Constraints

- 用户名加密码，暂不接短信；公开注册、独立账号和私有数据。
- 免费用户可输入文字、上传图片、手动排版、记录和打卡。
- 不覆盖可视化原型、早期 outputs/静愿 或 work/ 中的参考文件。
- 界面保持中文、苹方字体、粉紫背景、粗白标题和深色主按钮。
- 不实现或展示伪可用的 AI、联网搜索、支付与音频。
- 不购买、不公开部署付费服务；具体上线方案另行确认。
- 无 Git 仓库：代码实施前只为新 app/ 建立版本管理，不将用户图片、数据库、密钥纳入提交。
- 每项任务先写失败测试、最小实现、验证，再提交。出现范围变化先回到设计讨论。

## Review Focus

1. 伪造图片或文档 ID：不得跨账号读写，任务2、3验证。
2. 上传中断及保存失败：保留输入，不能虚报保存成功，任务3、4、6验证。
3. 重试和重复点击：同一打卡请求不重复计数，任务5验证。
4. 日期边界和并发修改：北京时间默认日期，冲突不覆盖旧值，任务4、5、6验证。
5. 密码与恢复码泄露：不以明文持久存储，不凭用户名重置，任务2验证。

## 文件结构与共享接口

- app/web/src/features/{auth,library,board,weekly,journal}/：按使用场景组织页面与状态。
- app/web/src/components/：共享导航、对话框、保存状态。
- app/server/src/features/：与网页同名的接口及数据访问。
- app/server/src/db/{schema.sql,migrations.ts}：数据结构和迁移。
- app/server/src/storage/private-files.ts：受控文件读写。
- app/shared/contracts.ts：请求响应类型，不复制两份接口。
- app/tests/e2e/：真实浏览器流程；app/server/tests/：接口与权限验证。

共同约定：ID 为服务端生成的不透明字符串；版本字段 version 为递增整数；日期 date 为 YYYY-MM-DD；时间戳用 UTC 保存，界面按 Asia/Shanghai 展示。错误格式为 {code,message}，409 表示修改冲突；未登录401，访问其他账号资源返回404。

## Task 2：独立账号、会话和恢复码

**Files:** server/src/features/auth/{routes.ts,service.ts,repository.ts}、server/src/db/schema.sql、web/src/features/auth/、server/tests/auth.test.ts。

**Interfaces:** POST /api/auth/register {username,password} → {user,recoveryCode}；POST /api/auth/login → {user}；GET /api/auth/me → {user}；POST /api/auth/logout；POST /api/auth/recover {username,recoveryCode,newPassword} → {recoveryCode}。使用 HttpOnly 会话 Cookie；写请求验证来源并使用 CSRF 防护。requireUser(request) 返回 userId。

- [ ] 定义用户名3–32字符、密码12–128字符，不修剪密码；用户名按规范化值唯一，显示名与登录名分离。
- [ ] 写失败测试：重复用户名、错误密码、退出后请求、恢复码错误/重放被拒、重置后旧会话失效、数据库没有明文密码与恢复码。
- [ ] 运行 npm test -- auth 确认失败。
- [ ] 实现可靠密码哈希、随机会话和单次恢复码，登录/注册/恢复设速率限制；错误登录不泄露账户是否存在。
- [ ] 实现注册登录、改密、恢复码展示与重置页面；页面不自动记录明文凭据。
- [ ] 运行 auth 测试；用两个账号验证会话隔离，全部通过后提交。

## Task 3：私人图片库和安全文件访问

**Files:** server/src/features/library/、server/src/storage/private-files.ts、web/src/features/library/、server/tests/library.test.ts。

**Interfaces:** POST /api/images 上传 → Image{id,width,height,bytes}；GET /api/images；GET /api/images/:id/content；DELETE /api/images/:id。文件内容响应先校验所属用户，存储目录不由网页服务器直接公开。

- [ ] 试用默认限制：JPEG/PNG/WebP，单图10MB、最大2400万像素，每账号200MB；作为配置而非无限承诺，上线成本确认时可调整并告知用户。
- [ ] 写失败测试：真实格式与扩展名不符、超限、跨账号访问、同名文件、部分上传失败清理；上传成功但元数据保存失败不得遗留公开文件。
- [ ] 运行 npm test -- library 确认失败。
- [ ] 实现内容格式和尺寸校验、随机文件名、受控缩略图、所属账号过滤、引用检查和软删除。
- [ ] 实现“我的图片”上传、选用、容量和失败重试界面；公共图库仅明确提示后续开放，不提供虚假素材。
- [ ] 测试通过，重启真实服务后验证图片仍可读取；确认原始文件未进入 Git，再提交。

**Interfaces:** GET /api/board → {version,elements}；PUT /api/board {version,elements} → 同结构。Element{id,type:'text'|'image',text?,imageId?,x,y,width,height,z,lit}；几何值为画布逻辑坐标，服务端验证图片归属。

- [ ] 写失败测试：8个独立元素保存重读一致、未授权图片被拒、无效尺寸被拒、旧版本写入409、取消点亮正确、删除可撤销。
- [ ] 运行 npm test -- board 确认失败。
- [ ] 实现按账号的画布保存与版本检查，原始图片和画布引用分离。
- [ ] 移植已确认的画布视觉，默认520像素；添加自动空位、扩展画布、拖动缩放、图层、输入尺寸、一键点亮与撤销。
- [ ] 实现保存状态与失败重试，网络异常保留草稿；冲突提示选择，不能静默覆盖。
- [ ] 运行接口测试及 npm run test:e2e -- board：上传3图、添加5组文字、移动、点亮、刷新、退出重登，核对布局；断网保存不丢输入。通过后提交。
